# ATS Damage — экспериментальная основа плагина

**Версия 0.1.0: телеметрия, русская панель и логика порогов. Реальная подмена материалов НЕ реализована.** Этот проект пока не добавляет вмятины, разбитые фары или порезы шин. Он не является готовым модом визуальных повреждений и не заявляет проверенную совместимость со всеми ATS 1.49+.

## Архитектура и выбор инструментов

C++17 + SPF Framework. SPF берёт на себя подключение SCS Telemetry, рендер Dear ImGui, ввод и конфигурацию. Плагин использует C API через таблицы функций: отдельная копия ImGui и прямой линкерный импорт SPF не нужны. Это избегает несовместимости контекстов ImGui и аллокаторов между DLL. Русский текст хранится в UTF-8; SPF загружает шрифт с кириллицей.

SPF headers зафиксированы на commit `1243098a897c625e5ddcab1fd4de4327bd0c8bb8` (версия в CMake upstream: 1.2.5). Не подменяйте их заголовками произвольного старого релиза. Нужен соответствующий runtime SPF; минимальная версия в манифесте — 1.2.5. Это ограничение фреймворка, а не номер версии ATS.

`main.cpp` получает snapshot телеметрии в render-loop SPF → `DamageSystem` рассчитывает требуемое состояние → `VisualBackend` должен применить материалы → `UI.cpp` показывает пороги и телеметрию. По умолчанию используется честный `UnavailableBackend`, всегда возвращающий отсутствие поддержки.

| Деталь | Источник | Ограничение |
|---|---|---|
| Бампер | `truck.wear.chassis` | Приближение по шасси; отдельного значения бампера нет |
| Фары | `truck.wear.cabin` | Приближение по кабине; не определяет сторону удара |
| Колёса | `truck.wear.wheels` | Среднее по колёсам; не состояние каждой шины |

Поля SPF: `SPF_TruckData.wear_chassis`, `wear_cabin`, `wear_wheels`. Значения нормализуются в 0…1; пороги — 1…100%. При достижении порога включается запрос эффекта; выключение происходит на 1 процентный пункт ниже порога или при ремонте до нуля. Выключение расчёта, пауза, исчезновение грузовика, смена его model ID и некорректные данные сбрасывают состояние. Два разных грузовика одной модели нельзя надёжно различить по model ID: будущему адаптеру понадобится реальный идентификатор экземпляра.

Система различает `requested` и `applied`: неудачное применение не выдаётся за успех. Никакие параметры физического урона, сохранения игры и неизвестные адреса памяти не изменяются. Telemetry wear нельзя без дополнительной проверки считать отдельными каналами damage/wear/permanent wear из системы ремонта 1.49.

## Автоматическая установка: run.bat

Скачайте **весь репозиторий** через Code → Download ZIP, распакуйте его в обычную локальную папку и дважды щёлкните `run.bat`. Один BAT без папки `scripts` и исходников не работает. Нужны Windows 10/11 x64, интернет, место для C++ Build Tools (несколько ГБ) и приобретённая ATS. Windows запросит UAC; используйте ту же учётную запись Windows, в которой установлен Steam.

Сценарий `scripts/run.ps1`:

1. Находит Steam и ATS, включая дополнительные библиотеки Steam. Если Steam отсутствует, устанавливает официальный клиент; если игры нет — открывает её установку в Steam и завершает работу с пояснением. Вход в Steam, приобретение игры и завершение её установки выполняет пользователь; затем снова запускает BAT.
2. Использует имеющийся CMake ≥3.24 или скачивает portable CMake 3.31.8 в `.setup`, проверяя SHA-256. Git, Python и winget не требуются.
3. Проверяет Visual Studio 2022 C++ и Windows SDK; устанавливает недостающее официальным Microsoft Build Tools installer с проверкой цифровой подписи. Установка может занять десятки минут. Если нужна перезагрузка, сообщает об этом и останавливается.
4. Загружает зафиксированные SPF headers, собирает `ATSDamage.dll` и запускает тесты. Ошибка останавливает установку.
5. Устанавливает SPF 1.2.5 из официального релиза с проверкой SHA-256 DLL. Уже установленный более новый SPF не понижает. Затем копирует наш плагин в `bin/win_x64/plugins/spfPlugins/ATSDamage/`. Чужие плагины не копирует и не удаляет.
6. Сохраняет заменяемые файлы в `.setup/backups/`, при ошибке копирования пытается восстановить их. Настройки и сохранения игры не изменяет.
7. Отправляет Steam команду запуска ATS. Левый Ctrl + левый Shift + D открывает панель при новой установке, Delete открывает SPF. Это запуск игры с плагином, не отдельное исполнение DLL.

Перед запуском закройте ATS. Если игра будет открыта во время установки, сценарий остановится. Отправленная Steam команда не является проверкой загрузки плагина: убедитесь в наличии панели в игре. Визуальные повреждения по-прежнему не реализованы.

Необязательные параметры из командной строки:

```bat
run.bat -GamePath "D:\SteamLibrary\steamapps\common\American Truck Simulator"
run.bat -NoLaunch
```

Журнал находится в `.setup/logs/`. Не закрывайте окно установки, пока не появится результат. Параметр ExecutionPolicy Bypass действует только на запущенный процесс PowerShell и не меняет системную политику. Политики организации и блокировки Windows скрипт не отключает.

Автоматическая установка на реальном Windows ПК и запуск игры здесь не проверялись; проверка синтаксиса и изолированные тесты сценария не заменяют этот прогон.

## Сборка Windows x64

Нужны Git, CMake 3.24+ и Visual Studio 2022 с компонентами Desktop development with C++ и Windows SDK. Команды выполняются из каталога распакованного проекта в PowerShell:

```powershell
git clone https://github.com/TrackAndTruckDevs/SPF-Framework.git external/SPF-Framework
git -C external/SPF-Framework checkout 1243098a897c625e5ddcab1fd4de4327bd0c8bb8
cmake -S . -B build -A x64 -DSPF_ROOT="$PWD/external/SPF-Framework"
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
```

Результат: `build/Release/ATSDamage.dll`. Собирается только наш плагин; исходники SPF используются как API headers, сам runtime отдельно устанавливается по инструкции SPF. Клонирование зависимостей SPF и сборка его CMake для плагина не нужны. Если runtime нужной версии ещё не опубликован, соберите именно зафиксированный upstream отдельно по его README. Не устанавливайте старый runtime, игнорируя проверку версии.

Для проверки только независимой логики на Linux/Windows:

```sh
cmake -S . -B build-core -DATS_DAMAGE_BUILD_PLUGIN=OFF
cmake --build build-core --config Release
ctest --test-dir build-core -C Release --output-on-failure
```

Полная сборка на Linux служит проверкой C++/API; Linux `.so` не заменяет Windows DLL и не является поддерживаемой сборкой для запуска этого проекта в ATS.

## Установка и панель

1. Установите совместимый SPF runtime по [официальной инструкции проекта](https://github.com/TrackAndTruckDevs/SPF-Framework#readme). Сохраните его структуру `spf-framework.dll`, `spfAssets`, `spfPlugins` в `American Truck Simulator/bin/win_x64/plugins`.
2. Создайте `American Truck Simulator/bin/win_x64/plugins/spfPlugins/ATSDamage/`.
3. Скопируйте туда `ATSDamage.dll`. Это SPF-плагин, а не самостоятельная SCS telemetry DLL: класть его непосредственно в верхний `plugins/` не нужно.
4. Запустите ATS с совместимым SPF. Панель первоначально видима. Сочетание **левый Ctrl + левый Shift + D** скрывает/показывает её. F7 больше не назначается плагином по умолчанию: в ATS эта клавиша открывает «Услуги и настройки».
5. Отрегулируйте три порога. Они сразу влияют на расчёт. Нажмите «Сохранить настройки» для сохранения между запусками. Изменения без нажатия кнопки не гарантированно сохраняются.
6. Взаимодействуйте с мышью через режим UI/курсора SPF согласно его настройкам. На паузе панель показывает «нет данных» по выбранной политике сброса.

**Обновление с прежней версии (F7):** SPF сохраняет пользовательские привязки, поэтому замена DLL не перезаписывает старую клавишу. Нажмите **Delete**, откройте настройки клавиш SPF, найдите **ATSDamage → «Показать панель повреждений» (`Panel.toggle`)** и замените старую привязку F7 на **левый Ctrl + левый Shift + D**. Именно замените F7, а не добавьте второй вариант. Сохраните настройки SPF. Пороги повреждений и остальные назначения сбрасывать не нужно. Можно выбрать другое свободное сочетание, если это уже занято у вас.

Если **Delete** тоже не открывает SPF, проблема не только в назначении клавиши: проверьте загрузку `spf-framework.dll` и `ATSDamage.dll`, а также журнал игры. По одному скриншоту игрового меню нельзя подтвердить, что плагин загрузился.

SPF хранит конфигурацию плагина. Текущая версия читает её при активации; внешнее редактирование требует перезапуска/перезагрузки плагина. Собственная панель полностью русская, язык служебных окон SPF настраивается отдельно.

**Ожидаемый результат сейчас:** панель показывает процент телеметрии и достижение порогов. Грузовик остаётся визуально прежним. Скриншоты не приложены: запуск в игре не выполнялся.

## Как добавить реальные повреждения

Официальный SCS Telemetry SDK предоставляет чтение телеметрии и базовые устройства ввода; публичного API смены материала грузовика в нём нет. SPF Hooks API даёт инструменты перехвата, но сам по себе не определяет функцию смены материалов. Нельзя заменить это выдуманным `SetTruckTexture()`.

Возможный путь — авторские повреждённые материалы для одной конкретной модели грузовика + проверенный перехват её назначения/отрисовки материалов. Подробный план, ограничения по LOD/зеркалам и критерии готовности: [docs/VISUAL_BACKEND.md](docs/VISUAL_BACKEND.md).

## Проверки и совместимость

Проверены на Linux: компиляция всех трёх `.cpp` по зафиксированным реальным SPF headers с `-Wall -Wextra -Werror`, тесты логики (равенство порогов, гистерезис, ремонт, ошибка применения, повторная попытка, выключение, потеря машины, NaN, нормализация настроек, отсутствие backend). Проверка компиляции не доказывает ABI/работоспособность в игре.

Windows/MSVC и реальный ATS здесь не запускались. GitHub Actions содержит сборку DLL, но до публикации и успешного прогона это только подготовленный workflow. Совместимость конкретных ATS build, рендереров и SPF runtime необходимо проверить отдельно; обещания «работает на всех 1.49+» нет.

## Первичная публикация на GitHub

Для нового пустого репозитория `aksa4y/ats-damage`, после распаковки и проверки:

```sh
git init -b main
git add .
git commit -m "Add ATS damage telemetry and Russian SPF panel prototype"
git remote add origin https://github.com/aksa4y/ats-damage.git
git push -u origin main
```

Если репозиторий уже содержит историю, сначала клонируйте его, перенесите эти файлы и создайте обычный commit; не используйте force push. GitHub потребует авторизацию вашей учётной записи. После push откройте Actions → Build → artifacts → ATSDamage-windows-x64. Репозиторий проекта: https://github.com/aksa4y/ats-damage.
