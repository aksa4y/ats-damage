# Настоящий визуальный адаптер: исследование, а не готовая реализация

## Что подтверждено

Телеметрия предоставляет агрегированный износ. UI API SPF рисует ImGui и позволяет работать с UI-текстурами; это не API назначения текстур игровому мешу. Hooks API позволяет искать сигнатуры и устанавливать перехваты. Наличие этих инструментов не доказывает наличие стабильной функции смены ассета.

## План для одного грузовика и одной версии ATS

1. Зафиксировать точный build ATS, SHA-256 исполняемого файла, рендерер, версию SPF, truck/accessory IDs. Выбрать одну конкретную модель и конфигурацию бампера, фар и колёс. Отключить адаптер при неизвестной комбинации.
2. Изучить модель и её материалы средствами SCS. Создать собственные damage-текстуры с теми же UV, форматами, mipmaps и цветовым пространством. Не публиковать извлечённые игровые ассеты. Diffuse/base-color передаёт царапины, normal — мелкие дефекты. Для изменения силуэта бампера необходим повреждённый mesh; одна normal map его не деформирует.
3. Найти и отладчиком подтвердить функцию назначения материала либо точку привязки texture resources при отрисовке конкретного accessory игрока. Не использовать глобальную замену texture pointer по одному хешу: один материал может разделяться AI-машинами и разными деталями.
4. Идентифицировать экземпляр игрока, accessory, submesh и LOD. Создать отдельный material/resource instance. Подтвердить ABI функции, владение ресурсами, поток выполнения, ссылочный подсчёт, уничтожение и повторное создание машины.
5. Реализовать `VisualBackend` на render thread. `supported()` возвращает true лишь после проверки build/renderer/model и успешной загрузки ассетов. `apply(part, damaged)` возвращает true только после реального применения. `restore()` восстанавливает оригинальные ресурсы и освобождает свои; повторный вызов безопасен. Не хранить сырой адрес грузовика после смены профиля/машины.
6. Для фар отдельно проверить стекло, emissive и световые источники: треснувшая текстура не выключает физический источник света. Для колёс использовать симметричный косметический эффект, пока нет данных о повреждении отдельной шины; не выдавать средний износ за определённое пробитое колесо.
7. Проверить main view, внешнюю камеру, зеркала, тени, LOD, ремонт, гараж, смену колёс, телепорт, загрузку сохранения, паузу, рестарт renderer и выгрузку плагина. Проверить, что AI и другие грузовики не затронуты. При несовпадении сигнатуры/нескольких совпадениях отключить backend.

Альтернатива для исследовательского прототипа: статический `.scs`-мод с повреждённой версией accessory, выбираемой в мастерской. Это позволяет проверить материалы, но само по себе НЕ обеспечивает динамическое переключение по телеметрии.

## Что не включено

Нет игровых адресов, непроверенных байтовых сигнатур, damage-текстур, `.scs`-мода и готового hook. Они зависят от конкретной установленной игры и модели. До выполнения плана нельзя называть эту версию реализацией визуальных повреждений.

## Ограничения текущего адаптера SPF

Поллинг использует кэш SPF. Идентификатор в TruckConstants — модель, не уникальный VIN экземпляра. Отсутствующие каналы могут иметь нулевые значения, которые неотличимы от исправного состояния; для production backend нужна отдельная проверка доступности каналов/сессии. Политика текущей панели сбрасывает состояние на паузе. Перед внедрением настоящего backend надо заменить её на управление ресурсами по событиям сессии и жизненного цикла машины, чтобы не перезагружать материалы каждый кадр меню.
